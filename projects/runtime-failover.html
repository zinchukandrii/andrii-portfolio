CASE STUDY / RELIABILITY

Resilient Runtime Failover Configuration

A provider-neutral tool for validating ordered runtime failover policies and simulating recovery paths without calling any provider.

Open repository ↗All projects
PROBLEM

Fallback lists are often copied into runtime configuration without tests, leaving real failure behavior unclear.

DESIGN

A strict JSON contract is validated before a deterministic simulator evaluates the ordered route.

BOUNDARY

No credentials, provider adapters, health probing or live traffic are accepted by the demonstrator.

OFFLINE SIMULATION

Recovery path: selected after two retryable failures.

01provider-a / qualitytimeout
02provider-b / balancedrate_limited
03provider-c / fastsuccess → SELECTED

CONTRACT

Configuration defects do not become a routing decision.

  1. 01

    Load

    Parse the configuration and stop on malformed JSON.

  2. 02

    Validate

    Reject duplicate route IDs, empty candidates and invalid numeric values.

  3. 03

    Simulate

    Consume declared outcomes only; no network call is made.

  4. 04

    Report

    Return SELECTED, BLOCKED or EXHAUSTED with the full attempt list.

MECHANICAL PROOF

Policy behavior is executable.

9tests passed
3retryable outcomes in the example policy
0provider calls in the simulator
3terminal states: selected, blocked, exhausted

LIMITATIONS

This is a policy-validation and simulation tool, not a production traffic router. Production adoption requires approved adapters, secrets management, telemetry and an explicit rollback plan.
