CASE STUDY / ENGINEERING DATA

Synthetic Quality Observability Platform

A synthetic engineering-data demonstrator that validates traceable production records before surfacing quality, anomaly and drift signals in a responsive dashboard.

Open repository ↗All projects
PROBLEM

A dashboard is not trustworthy when its quality metrics are derived from structurally invalid or untraceable records.

DESIGN

Deterministic synthetic data flows through fail-closed validation, drift checks, a local DuckDB analytical model, analytics endpoints and an API-driven dashboard.

BOUNDARY

Synthetic fixtures only. No employer, client, production-line, product or operational data is used.

ARCHITECTURE

Data must pass a contract before it becomes an operational signal.

  1. 01

    Generate

    Create deterministic production runs, batches, inspections, defects and AOI-like signals using a fixed seed.

  2. 02

    Validate

    Reject broken schema, ranges, foreign keys and trace relationships before reporting a quality result.

  3. 03

    Model

    Materialise synthetic-only stage tables, dimensions, facts and a run-quality mart in local DuckDB; store executed integrity checks.

  4. 04

    Analyse

    Calculate inspection, defect, anomaly and drift indicators from the accepted synthetic dataset.

  5. 05

    Expose

    Serve an inspectable dashboard and API with an explicit synthetic-data classification.

MECHANICAL PROOF

A data product with visible limits.

LIMITATIONS

This is a portfolio demonstrator, not a deployed manufacturing execution system. Its synthetic metrics demonstrate data contracts, observability and dashboard design — not real process performance.
